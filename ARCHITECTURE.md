# Architecture

This file describes the code **as it is now**. The target layout is in [SPEC.md §2](SPEC.md#2-architecture); update this file whenever a slice changes the structure.

## Workspace

A Cargo workspace (`Cargo.toml`) with two crates. Shared dependency versions, package metadata and lints live in the root `Cargo.toml` (`[workspace.dependencies]`, `[workspace.package]`, `[workspace.lints]`); each crate opts in with `.workspace = true` / `[lints] workspace = true`.

| Crate | Path | Kind | Role |
|---|---|---|---|
| `rappel-core` | `crates/core` | library | All logic. No UI dependency, testable with plain `cargo test`. |
| `rappel` | `crates/app` | binary | GTK4 + libadwaita front end. Talks to core only. |

`third_party/ratex-cairo` is a vendored copy of the `ratex-cairo` crate with `cairo-rs` bumped to 0.22 (ADR 0021, `VENDORED.md` there). It is not a workspace member (`exclude = ["third_party"]`) and is used through `[patch.crates-io]`.

Dependency direction: `rappel` → `rappel-core`, never the reverse. `rappel-core` must not depend on gtk4, glib, gio, libadwaita or anything UI.

### `rappel-core` today

Only what a front end or `examples/` uses is `pub`; everything else is `pub(crate)`, and code that only tests need is `#[cfg(test)]` (e.g. `is_valid_app_id`). Make an item `pub` in the slice that first needs it outside the crate.

- `src/lib.rs`: the app name and ID constants (its tests check `APP_ID` the way `g_application_id_is_valid` does); re-exports `Error` and `Result`.
- `src/test_support.rs` (test builds only): helpers shared by several modules' tests: `T0`, `DAY_MS`, `scheduled`, `answer`, `schedule_table`, `dump` (every row of every table in `sqlite_master` with its `rowid` where the table has one, the search index's own tables and `card_schedule` included, the schema itself and its version: two databases compared whole, ADR 0066), `with_suffix`, `within` (runs hostile input on a 512 KiB stack; fails the test past a CPU-time limit, or past a separate wall-clock hang timeout, `hang_limit`; ADR 0025, ADR 0049), `fastest` (the least CPU time of a few runs), and the time-bound helpers of ADR 0049: `thread_cpu_time`, `cpu_time_between` and `cpu_time_of` (the thread's CPU time, from `/proc/thread-self/schedstat`, else `stat`, else the wall clock; a clock that does not move counts as missing), `slowdown` (how much slower than the machine the bounds were set on this thread runs now, from a reference workload) and `cpu_within` / `assert_cpu_within` (a CPU time checked against a bound at that speed, through the pure `judge`). `RAPPEL_TIMINGS=1` prints the times; `Hook` and `set_hook` (a test hook set until its guard drops: `import::BEFORE_READ`, the Anki import's `AFTER_CARD`, `BEFORE_COMMIT`, `BEFORE_CHECK`); `learn` (two Passes: a card in review) and `tag_id` (ADR 0073); `png_bytes`, `wav_bytes`, and `cpu_within_retried` (a bound tried `TRIES` times). Use them instead of a local copy, and never a wall-clock bound in a test.
- `src/error.rs`: the crate-wide `Error` enum (`thiserror`) and `Result` alias. `Random` boxes its cause so `getrandom` stays out of the API; `rusqlite` and `fsrs` errors stay visible (ADR 0015).
- `src/auto_backup.rs` (ADR 0080): the automatic backup to a folder the user chose. Pure: `LocalDate` (a local calendar date; `from_utc_ms` with a UTC offset, `parse` of `YYYY-MM-DD`), `file_name` / `parse_file_name` (`Rappel backup YYYY-MM-DD.rappel`, exactly), `to_delete` (all but the `KEEP` = 14 newest by the date in the name, never the one just written), `due` (none today to this folder; a last backup up to `MAX_ZONE_SPREAD_DAYS` = 2 days ahead counts as today's, one further ahead does not) and `changed` (the fingerprint differs), `kind_of` (an IO error to a `FailureKind`), `is_partial_name` and `stale_partials` (the job's own partial files, by their exact pattern, untouched for `STALE_PARTIAL_SECONDS` = a day; ADR 0084), and `inside_data_dir` (a folder that is the data directory or inside it, by path with links resolved and by device and inode up through `..`; Preferences refuses such a folder with it). Only `LocalDate`, `LastBackup`, `due`, `run`, `Outcome`, `Failure`, `FailureKind` and `inside_data_dir` are `pub`. `run` (with a cancel flag; the folder as the app stored it, links resolved) checks the fingerprint first, then opens the folder once (`O_DIRECTORY | O_NOFOLLOW`), refuses it inside the data directory (`InsideDataDir`), and works relative to that handle with `rustix` (`openat`, `renameat2` with `RENAME_NOREPLACE` and a checked plain `renameat` where the flag is unsupported, `statat` without following links, `unlinkat`): the export (`Store::export_into`) to a hidden random `.partial` file, synced, renamed without replacing, the folder synced, then the old backups pruned (regular files of the exact pattern only) and the stale partial files removed (also when today's backup was already there; never after a failure). Returns an `Outcome` (`Unchanged`, `AlreadyThere`, `Written`) or a `Failure` (kind and English detail). `AFTER_EXPORT` is a test hook between the export and its rename. `auto_backup/tests.rs`: the pure rules, once a day across time zones and a leap day, the fingerprint seeing each kind of change, a folder full of links, look-alikes, a link or file in the folder's place, read-only or removed (also while the backup runs), a full disk (`/dev/full`), 20,000 entries, odd names, a FIFO or socket in its place, killed backups' partial files, and the data directory reached every way (ADR 0084).
- `src/data_dir.rs`: `resolve_data_dir` (pure; takes a `DataDirEnv` and a `BuildProfile`) and `ensure_data_dir` (creates a directory with mode `0700`). Debug builds refuse the release directory and the pre-rename `cards` one. See ADR 0004 and ADR 0020.
- `src/id.rs`: `IdGen`, strictly increasing `UUIDv7` strings (a 122-bit counter with random low bits; `observe` raises it above an id read from the database). See ADR 0008. `uuid_v7_value` checks ids from outside (an import, ADR 0017) and gives their 122-bit value, which compares as the string does (ADR 0053); `format_id` turns a value back into its string.
- `src/time.rs`: `now_ms` (UTC milliseconds), `utc_parts` (calendar fields from milliseconds) and its inverse `utc_ms`.
- `src/domain/`: shared types, `name_key` (the uniqueness key of deck and tag names; `deck_name_key` is an alias), and the length limits shared by the store and the import (`MAX_DECK_NAME_BYTES`, `MAX_CARD_SIDE_BYTES`, `deck_name_fits`, `card_side_fits`, `CardSide`; ADR 0018): `Deck` (with `archived_at` and `is_archived`, ADR 0068), `ArchivedDeck` (an archived deck and its card count), `DeckSummary` (deck, new/due counts, card, suspended and held-back counts, and the next study change; ADR 0041), `Card` (with `suspended`, ADR 0035), `Grade` (Fail/Pass), `ReviewEvent` (one log entry, with `EventKind`: `Review(Grade)`, `Reset` or `Undo { undoes }`, ADR 0028), `Phase`, `CardState` (`New` or `Scheduled(Schedule)`), `Settings` with its defaults, ranges and `check_*` functions and `SettingKey`, the stored keys (`domain/settings.rs`, ADR 0027, 0052), and `Tag` with `check_tag_name` and `MAX_TAG_NAME_BYTES`, `TaggedCard`, `parse_tag_field` (a comma-separated field to names) and `search_key` (the accent- and case-insensitive key for suggestions) (`domain/tag.rs`, ADR 0029, 0031).
- `src/scheduling/`: FSRS scheduling (ADR 0006), using the `fsrs` crate.
  - `mod.rs`: `Scheduler` (desired retention, default FSRS-6 parameters; built per transaction from the stored retention by `storage::settings::scheduler_in`, ADR 0027). `schedule(card_id, state, grade, now)` gives the state after one review; `rebuild_state(card_id, events)` replays a card's log: `surviving` drops undos and the entries they cancel and orders the rest, then reviews fold `schedule` and a reset gives New (ADR 0028). 10-minute step for new and failed cards; elapsed days are rounded 24-hour periods. A Pass on a review card is at least elapsed + 1 days, before and after fuzz (ADR 0009).
  - `fuzz.rs`: deterministic interval fuzz (Anki's ranges, seeded from card id + review count).
  - `session.rs`: the study session, pure (no SQL, no clock): `StudyInput`, `interleave` (new cards spread evenly among reviews), `Session` (`next(now)`: due step cards, then the queue, then step cards up to 20 minutes early; `skip` drops a card without counting it and `put_back` brings it back as the next one (suspend and delete during review, ADR 0037); `graded` re-queues cards left in the 10-minute step and remembers what it changed, so `last_answer` / `undo_last` take the newest answer back exactly and pin that card as the next one, `forget_answers`; ADR 0030), `Summary`, `capped` (60 s), `allowance` (what is left of a daily limit). The module is crate-private; `scheduling` re-exports what the app uses (`StudyInput`, `Due`, `Session`, `Summary`, `capped`). Tests in `session/tests.rs`. See ADR 0014.
  - `scope.rs`: what a session covers, `StudyScope` (`Deck(id)` or `Tag(id)`, re-exported by `scheduling`), and `allocate`, pure: a tag session's input from each deck's `DeckAllowance` (what is left of its own limits today) and the `Candidate` cards (suspended, deleted and those of a deck without an allowance left out), each deck cut to its allowance in its own order, then merged as a deck session orders them. Tests (and two property tests) in `scope/tests.rs`. See ADR 0069.
  - `practice.rs`: practice (ADR 0070), pure and in memory: `practice_order` (from `PracticeCandidate`s: reviewed cards by retrievability, lowest first, then new cards by `seq`, ties by id, at most `PRACTICE_LIMIT` = 50) and `Practice` (the queue, each card at most once; `graded` keeps the answer for the summary, a Fail bringing the card back after `RELEARN_GAP` = 3 cards; `undo_last`, `skip`, `put_back`, `summary`). It holds no store, so it cannot write. Tests and an undo property test in `practice/tests.rs`.
  - `tests.rs`: FSRS reference values and property tests (rebuild = review-by-review; with undos and resets, rebuild = the fold of the counted reviews, #11).
- `src/content/`: card Markdown → `Document`, a UI-agnostic block/inline tree, with `pulldown-cmark` (ADR 0019). No UI.
  - `mod.rs`: the tree (`Document`, `Block`, `Inline`, `ImageTarget`, `Align`) and `MAX_DEPTH` (16), the nesting cap. An image whose target is a `media:` reference to an image kind is `ImageTarget::Media(MediaRef)`, a link to an audio kind is `Inline::Audio` (ADR 0054); `media_refs(md)` lists every valid reference of a side's image and link targets, each once, in order.
  - `parse.rs`: `parse(md)`, a stack of open containers over the parser's events. Raw HTML becomes literal text, NUL becomes U+FFFD, `$$…$$` alone in a paragraph becomes a `DisplayMath` block, inline math closed by a `$` followed by a digit is text (`$5-$10`), and containers past the cap are flattened into the deepest one.
  - `plain.rs`: `plain_text` (no syntax, for screen readers) and `search_text` (the plain text folded by `domain::search_key`, what the search index holds, ADR 0035) and `plain_summary` (one line, at most `PREVIEW_CHARS` = 200 characters, from the first 16 KiB, for the card list) and `one_line_summary` (the same from a `plain_text`).
  - `summary.rs`: `summary` (ADR 0077): the same one line as `plain_summary`, but as `SummaryPiece`s, text and formulas apart, so a card list row draws the formulas (#128), with its plain text (formulas as their source) for screen readers; a formula that starts before the 200-character cut is kept whole, one after it is left out, and one longer than `MAX_SUMMARY_FORMULA_BYTES` is text.
  - `tests.rs`: each construct, untrusted HTML, dollars, the cap, property tests (never panics, within the cap), and 1 MiB hostile sides (`hostile_sides`) and random syntax repeated to 256 KiB, parsed within a time bound on a small stack, with node and text counts bounded by the input (ADR 0025).
- `src/media/`: the media store (ADR 0054) and its trash (ADR 0057). No UI.
  - `mod.rs`: `MediaRef` (a SHA-256 and a kind; `parse` of a `media:<64 lowercase hex>.<ext>` URL, `file_name`, `reference`), `MediaProblem` (empty, not media, not an image, not audio, damaged audio, more than plain audio, too large), `hex` / `parse_hex`.
  - `kind.rs`: `MediaKind` (PNG, JPEG, WebP, GIF, Ogg with Opus or Vorbis, MP3, M4A, WAV; one extension and one MIME type each; `detect` from the first `DETECT_BYTES` (512) only), `IMAGE_MAX_BYTES` (10 MB) and `AUDIO_MAX_BYTES` (20 MB).
  - `store.rs`: `Store::add_media` / `add_media_bytes` (through `ingest_then`: a new temporary file in `<data dir>/media/`, the kind from the first bytes, capped and hashed while copied (`copy_capped`; an audio file is also kept in memory and must pass `check_structure`), synced, then, under the database's write lock (`ingest_then`, ADR 0057), named `<sha256>.<ext>` by a hard link that never replaces a file; a damaged file of that name is kept under a second name), `MediaBatch` (an import's new files: each copied and checked as `ingest_then` does, then synced together, 128 at a time on up to 64 threads, before any is named; the folder synced once at `finish`; unnamed ones removed when dropped; ADR 0063), `insert_media_row` (the `media` row, the first `created_at` kept), `Store::add_image` and `add_audio` (the editor's Insert Image… and Insert Audio…: a file of the other kind refused as `NotImage` / `NotAudio` before anything is written, then `add_media`, ADR 0056; ADR 0055), `Store::media_path`, `Store::media_folder`, `sync_folder`. Folder `0700`, files `0600`.
  - `bytes.rs`: the bounds-checked readers of numbers in a file (`u16_be`, `u32_le`, …) the three modules below share.
  - `dimensions.rs`: `image_size`, an image's width and height from its header (PNG `IHDR`, a JPEG's first `SOFn`, WebP `VP8 ` / `VP8L` / `VP8X`, a GIF's screen and first image), read before anything decodes it (ADR 0063); tests with Pillow's images in `fixtures/images/` (their README has the script).
  - `color.rs`: `without_color_profile`, an image without its ICC profile (PNG `iCCP`, JPEG `ICC_PROFILE` segments, WebP `ICCP`), which glycin would unpack into the app's process and parse there with lcms2 (ADR 0063).
  - `structure.rs`: `check_structure` (ADR 0056), whether a whole audio file is plain audio of its kind, and `audio_payload`, the part of it a player is given (an MP3's frames without its tags, ADR 0062): MP3 frames after ID3v2 tags (an APE tag whose items fill its size and an ID3v1 tag at the end), one Ogg Opus or Vorbis stream with every page's CRC, a RIFF WAVE of PCM or float, M4A boxes from an allow-list per parent (no compressed movie, reference, redirect, fragment or other track). Pure, one pass, never panics; `structure/tests.rs` with real files from `fixtures/` (made with GStreamer's encoders) and hostile ones (playlists and manifests behind an ID3 tag, chained Ogg, M4A redirects).
  - `used.rs`: what a database uses (ADR 0057): `side_hashes` (`content::media_refs` plus any `media:` + 64 hex digits in the text), `card_hashes` (every card, live or deleted; only sides with `media` or `&` are parsed), `row_hashes` (none without a `media` table, as in old backups), `used_hashes`.
  - `trash.rs`: unused media and the trash `<data dir>/media-trash/<YYYY-MM-DD>[-N]/` (ADR 0057): `Store::unused_media` (`UnusedMedia`), `Store::clean_up_media` (one write transaction: the unused set found again, renames into a free place of the day's folders, syncs, rows deleted; on failure the rows roll back and the files move back; a `Mover` and a hook before the commit are injected by tests), `Store::undo_clean_up` (`CleanedUp`), `recover_rows` (at open), `recover_all` (restore, import, startup), `recover_refs` (card writes); a file comes back only if its content has its name's hash; unreadable trash folders are skipped, `trash_day` (a clean-up's folder dated the latest of today, the newest folder and the database's `latest_time`), the purge (`purgeable`: the clock 31 days after the folder's date and the database's newest user action 30 days after it; `read_copies`: every backup, the waiting restore copy and the other database copies, read-only, an unreadable backup blocking it; the files deleted under the write lock: the only deletion of a user's media file) and `Store::tidy_media_trash` (`TrashTidied`).
  - `tests.rs`: each kind, hostile signatures (SVG, HTML, polyglots, video), references, the store's files and rows, an existing file never overwritten, the table's CHECKs. `trash_tests.rs`: what is unused, every crash window of a clean-up, undo, an add and a clean-up on two connections, bringing back (open, restore, import, card writes), the purge (30 days, backups, unreadable backups, the database's own use), hostile names, the 20,000-card time bound.
- `src/stats/`: statistics over the log, pure (ADR 0032).
  - `mod.rs`: `DayGrid` (strictly increasing day starts from the caller; `day_of` by binary search), `DayActivity`, `Stats` (`Stats::compute`: days, pass rate, forecast, overdue, scheduled cards, expected retention), the pure pieces (`activity_by_day`, `pass_rate`, `due_forecast`, `retrievability` with the `fsrs` crate's `current_retrievability`, `expected_retention`) and two rules for one card's log: `counted_reviews` (its memory side: after the last surviving reset, for a card's reps) and, in tests, `activity_reviews` (every review no undo cancels; ADR 0032).
  - `card.rs`: `CardInfo`, `HistoryEntry` (`Review` / `Reset`) and `card_info`, which replays the surviving log with the scheduler.
  - `tests.rs`: bucket edges, 23- and 25-hour days, forecast, retrievability against the scheduler's interval, hand-made logs, property tests of the grid.
- `src/interchange/`: export and import of the whole database as a `.rappel` file (ADR 0017; ADR 0020 for `.cards`, which still imports), with its media files (ADR 0054), and the import of Anki packages (`anki/`, ADR 0061). `export.rs` also has `Store::export_into` (an export made at a given time into a file already open, for the automatic backup; an IO error writing it is an `Error::Io` on the export's own file, ADR 0084) and `collection_fingerprint` (the SHA-256 of `cards.json` with `exported_at` 0 and every media record: changes exactly when an export would; ADR 0080). The import streams the file and keeps compact notes, so its memory is bounded (ADR 0053). No UI.
  - `mod.rs`: the public types (`ExportSummary` (with the media written, those left out on purpose and those missing or damaged), `ExportOptions`, `ImportPlan` (the summary, a fingerprint of the file and a digest of the decisions, no content) and its `ImportSummary` with `TableCounts` and `Conflict`s, `ImportReport`, `ImportProblem` / `FieldProblem` for a refused file; the Anki import's types re-exported, and `file_kind`, which tells a Rappel export from an Anki package by extension, else content) and the internal `MAX_ARCHIVE_BYTES` (2 GiB, shared by the import's limit and the export's check, ADR 0071) and `Limits` (archive 2 GiB, 100,000 entries, a 16 MiB central directory, 256 MiB of JSON, one image 10 MB and one audio file 20 MB for the media import, text sizes).
  - `format.rs`: the serde types of `cards.json` (`FORMAT_VERSION` 2), fields in file order, unknown fields denied: decks, cards (with `suspended`, defaulting to false when a file lacks it, ADR 0035), tags, card tags, log entries (`kind`, `grade`, `undoes`), the typed `SettingsRecord` and `MediaRecord` (`hash`, `mime`, `bytes`, `created_at`, ADR 0054); `Document`, the whole file, which export writes. Version 1 (`EARLY_TEST_VERSION`) is refused, not read (ADR 0017).
  - `archive.rs`: writes the zip deterministically with the `zip` crate (`ArchiveWriter`: `cards.json`, `media/`, then each media file `media/<sha256>.<ext>` stored, fixed timestamp and permissions). `Archive` reads one with our own code, from its file through a `Window` (nothing past the checked size): the end record, which must end the file (a classic one, or a zip64 one exactly where the writer puts it; no other end record is ever read; the entry count and the central directory's size refused there against the limits), then the central directory walked record by record (`walk_directory`: exactly the declared count, filling exactly the declared size, each name compared as bytes at once and never kept (a media name parsed into its hash and kind, `Role::Media`; media names twice found by sorting them by hash, `media_by_hash`), zip64 sizes from the extra field; a media entry empty or declaring more than its kind's limit refused there), then each entry's local header (`Entry`: role, method, CRC, declared size, the bytes it takes), and entries that do not overlap and end before the directory. `open_entry` streams an entry's data (Stored, or Deflate through `flate2`) with a hard cap, its SHA-256, and its CRC and size checked at its end, failing as soon as it gives more than it declares (`EntryReader`, ADR 0063); `copy_entry` streams one to a writer, for the media import. `media_entries` / `media_entry` give the media entries in hash order. `Window` reads past a forward seek of at most 32 KiB instead of seeking, so a buffered reader keeps its buffer over many small entries. a `cards.json` that declares more than `Limits::json` is refused from the central directory (ADR 0071), as a media file is. `Archive::open_anki` reads an Anki package's layout instead (`Layout::Anki`, `AnkiName`): Anki's names each once (other names passed over, never read), at least one collection, numbered media files by number (`anki_entry`, `anki_file`).
  - `source.rs`: `Source` (the user's file, or bytes in tests), opened again by each pass; only a regular file (`NotAFile` otherwise); its `Stamp` (size, modification time, device, inode).
  - `stream.rs`: `cards.json` as a stream: a serde visitor over the top-level object and each list, handing each record (parsed with its `format` type) to a `Sink` and dropping it, with a `Focus` (everything in one pass, the shape only, or one list); `Header` read alone; the reader under serde_json (`JsonInput`) refuses a string longer than any field can be (`string_limit`, six times the longest text limit) and nesting deeper than `MAX_DEPTH` (1,024); `ReadEnd` says what one read found, in the order the checks come (the archive, a string too long, the JSON).
  - `validate.rs`: the checks of one row that need no other row and no database, one function per table (`deck_fields`, `card_fields`, `tag_fields`, `event_fields`), in the order the checks have always run, and `check_id`, the top level and the settings.
  - `media.rs`: the media of an import (ADR 0054): `MediaList`, the `media` records checked as they stream by (`validate::media_fields`: hash, sorted and once, type, size, time) with a 56-byte note each, at most as many as the archive has media entries; `check_entries` pairs records and entries by hash (names, sizes); `check_contents`, in the plan, reads every media entry once without writing it (its first bytes of the record's type, an audio entry kept whole, at most 20 MB, and plain audio by `check_structure`, its SHA-256 the record's hash); `store_new_media`, in the apply's transaction, streams each new file into the media folder through a `media::MediaBatch` and inserts its row.
  - `notes.rs`: what the import keeps of the rows read (`Notes`): ids as values in vectors sorted once their table is read, name keys as 64-bit digests, 32 bytes per log entry (`EventNote`) and per undo (`UndoNote`); `seal` sorts a table's notes and returns the values seen twice (`Candidates`), which `Locate` confirms on a second read of the table, row by row, in memory fixed by the number of candidates (a flag per id, a 128-bit hash per name digest).
  - `engine.rs`: `Engine`, the `Sink` of a plan or an apply: each row checked (with the notes for uniqueness, references and undo targets), compared with the database by id (new, present, revived or a conflict; tags mapped by name key; the cards deleted with a revived deck after the cards; deck name conflicts listed last), each decision added to a SHA-256 digest, and, applying, written at once (undos after the whole log, in id order); `classify_media` compares each media record with the `media` table by hash (new, present, or `Conflict::MediaDiffers`) after the lists. `Stop` says why it stopped a read (read again step by step, a problem, candidates to confirm, a stale plan, the database).
  - `import.rs`: `Store::plan_import` and `plan_import_cancellable` (an `AtomicBool` makes the file's reader (`source::Cancellable`) fail at its next read, and the plan is then `Error::ImportCancelled`, ADR 0071; reads in one pass a file as an export writes it, else step by step in the order of the checks: the version alone, the shape, the top level, each list, the settings, with an engine that only checks (`checks_only`), then each list again compared with the database; no writes) and `Store::apply_import` (no-op if nothing is new or revived; else the same stamp, a backup, then one transaction that reads the file again the same way and writes row by row, refused with `ImportPlanStale` if a decision differs from the plan's and `ImportFileChanged` if the file did; then the settings when the plan applies them and the schedules of cards with new entries via `storage::rebuild_cards`). `compare` is the merge rule of a deck or card whose id the database has; a card that differs only in its deck (or `suspended`) is compared without it and keeps the database's deck, revived only into a deck live after the import (`engine.rs`'s `classify_card`, ADR 0067); a deck is compared without `archived_at`, which the database keeps (`classify_deck`, ADR 0068). `format.rs`'s `ArchivedAt` reads any JSON value for a deck's `archived_at`, so `validate::archived_at` refuses a wrong type as the field (`FieldProblem::NotATimestamp`).

### `rappel` today

Pages live in `src/pages/`, dialogs in `src/dialogs/`, reusable widgets in `src/widgets/`, and helpers shared by all of them in `src/ui/`. ## UI build pipeline

UI layout is written in Blueprint, never in Rust code or hand-written `.ui` XML.

```
data/*.blp ──blueprint-compiler──▶ $OUT_DIR/ui/*.ui ──glib-compile-resources──▶ $OUT_DIR/rappel.gresource
                                                                                  │
                                         gio::resources_register_include! ◀───────┘ (embedded in the binary)
```

`crates/app/build.rs` drives both steps; `data/resources.gresource.xml` lists the files under the resource prefix `/io/github/rappelapp/Rappel/`. Widgets load their template with `#[template(resource = "/io/github/rappelapp/Rappel/<name>.ui")]`.

`build.rs` also compiles each language of `po/LINGUAS` (the repository's `po/` folder: `LINGUAS`, `POTFILES.in`, `rappel.pot`, `<lang>.po`) into `$OUT_DIR/locale/<lang>/LC_MESSAGES/rappel.mo` with `i18n/po.rs`, rerunning when `po/` changes; a debug build reads its translations from there (ADR 0059). Strings in `.blp` files are marked `_("…")` or `C_("context", "…")`; `GtkBuilder` looks them up in the default domain.

`build.rs` runs both tools itself (no `glib-build-tools`). It tells Cargo to run it again when `data/` (as a directory, so a new or removed file counts), any `data/*.blp`, `data/resources.gresource.xml` or a file the manifest bundles from `data/` (`style.css`) changes; the `.ui` files it writes to `OUT_DIR` are not listed, so one edit costs one build. The crate is then compiled again because `gio::resources_register_include!` includes the gresource with `include_bytes!`. Cargo goes by modification times, so a file copied in with an older time is missed (`cargo clean -p rappel`, README); `ui_files.rs` catches the mismatch in the gate (ADR 0047).

Files of two kinds live in `data/`: composite templates (a `template` block, loaded by `#[template]` when the widget is built) and plain layouts that `ui::dialog::builder` loads (alert dialogs, Preferences, Card Information, the shortcuts dialog). Each plain layout is loaded by one function next to the code that uses it (`card_info::Layout::load`, `browser_dialogs::choose_layout`, `merge_deck::layout`, `transfer::confirm_layout`, …) or, for an alert that is the only object of its file, by a named `ui::dialog::Alert` constant (`CLEAN_UP_MEDIA`, `DELETE_CARD`, `DISCARD_CHANGES`, `EXPORT_WITHOUT_MEDIA`, `RESTORE_BACKUP`, `START_FRESH`). `src/ui_files.rs` (tests only) lists every `data/*.blp` file with how it is loaded and checks that each is in the gresource and loads: a template widget is built, which runs gtk4-rs's checks of its `#[template_child]` ids and types (a mismatch aborts the test binary with the id in its message), and a plain layout goes through its loader, which logs each object it looks up that is missing or of another type and returns `Err` with the first one's id, which the test names. A `.blp` file with no entry fails the test.

## Quality gate

`scripts/check.sh` runs `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings` (with `clippy::pedantic`, `unwrap_used`, `expect_used`, and `allow_attributes` / `allow_attributes_without_reason`: a lint is silenced only by `#[expect(.., reason = "..")]`, which fails the build once it is no longer needed), `cargo test --workspace --locked` and `cargo deny --locked check -D license-exception-not-encountered` (licences compatible with GPL-3.0-or-later, RustSec advisories, crates.io only; the `-D` makes an unused licence exception an error, so a changed `OFL.txt` hash for the KaTeX fonts cannot pass silently, ADR 0023). `third_party/` (vendored code, ADR 0021) is a workspace `exclude`, so none of these steps checks it. `scripts/screenshot.py` (batch mode only, run with `python3 -I`; `--env` passes e.g. a French locale, `--decoration-layout :close` shows GNOME's window buttons) starts the app on a private Xvfb display (a free number Xvfb picks itself, with a fresh authorization cookie) with a copied or new scratch database, a given size and colour scheme, and a home folder of its own; it sends keys and clicks only through XTest on that display (the app gets no session bus or AT-SPI), cleans up on every exit, and refuses real data folders, and saves screenshots to the git-ignored `docs/briefs/screenshots/`; its `resize:W,H` step resizes the app's window as an on-screen keyboard does (ADR 0058). `scripts/pre-commit.sh` refuses commits on `main` and then runs the gate; `scripts/install-hooks.sh` installs it. `.github/workflows/ci.yml` runs the same `scripts/check.sh`, under Xvfb (`xvfb-run -a`), on every pull request and on pushes to `main`, in an `ubuntu:26.04` container with the README's system packages and stable Rust (see ADR 0003). Some tests start GTK, so the gate needs a display (ADR 0024). They go through `crates/app/src/testing.rs` (test builds only): one thread owns GLib's default main context and runs their bodies one at a time, because `gtk::init` keeps that context for good. `testing::with_gtk` runs a body there with GTK started (`on_main_context` without it), held to X11 whenever `DISPLAY` is set (so `xvfb-run` in a Wayland session never puts the tests on the compositor) and to GTK's own input method (the session's IBus or Wayland text input answered after a test's window was gone and crashed the binary; ADR 0024, amended); `testing::with_widgets` also starts libadwaita and registers the app's resources (once per run), for tests that build its widgets or load its `.ui` files: every such test goes through it, none calls `adw::init` or `resources_register_include!` itself; `testing::thread_cpu_time` and `cpu_time_of` read the thread's CPU time, and `testing::assert_cpu_within` / `cpu_within` check it against a bound at the speed of the machine the bounds were set on (`slowdown`, through the pure `judge`), so time bounds hold under load (ADR 0049); call them on the thread that did the work; `testing::settle_until` runs the main context until a condition holds or a timeout passes (waiting on GTK, not timing). `testing::run_alone` runs one test alone in a new process of the test binary with a configured environment and fails unless it passed (fresh GTK types, GStreamer's variables, a locale, an abort). `testing::temporary_state` opens a new database in a temporary directory, `testing::state_with_many_cards` one with a deck of many cards written in one transaction (ADR 0073), and `state_with_cards` the same with given sides and tags, `math_side` a side full of math (ADR 0084); `testing::strings` and `card_rows` are small shared helpers; `menu_item_sensitive` reads a menu item's state; `testing::descendants`, `label_texts` and `settle` walk and settle what a test built; `on_main_context` reports a body's panic, with its place, on the test's own thread (ADR 0073); and `testing::png_bytes` encodes a real PNG with GDK, and `testing::wav_bytes` writes a WAV of silence. `testing::within` (and `within_stack`, with a stack size of its own) runs a test's work on `SMALL_STACK` with a CPU-time bound and a separate wall-clock hang timeout (`hang_limit`), as `rappel-core`'s `test_support::within` does; `RAPPEL_TIMINGS=1` makes them and `print_timing` print the times.
