# 86. Icon names in the snap

- Status: Accepted
- Date: 2026-11-10
- Refers to: ADR 0085 (the snap), ADR 0082 (feasibility); the 0.4.2 request "icons missing in the snap"

## Context

In the snap, GTK draws icons from `gnome-core26`'s Adwaita, not the host's theme. It was reported that some symbolic icons show as "image missing" there: the decks page's empty state (`accessories-dictionary-symbolic`) and two buttons in the review header. The plan was to check every name against what `gnome-core26` ships, switch to an Adwaita equivalent where one exists, and bundle a symbolic SVG in the GResource for the rest.

## Finding

`snap download gnome-core26` (revision 33, stable) and `unsquashfs -l` on `usr/share/icons/Adwaita` list every one of the 30 `*-symbolic` names Rappel uses in its Blueprint files and Rust sources, including `accessories-dictionary-symbolic` (in `symbolic/legacy`, which `index.theme` lists under `Directories`) and the review header's `edit-undo-symbolic`, `view-more-symbolic` and `document-edit-symbolic`. So no name needed switching and nothing was bundled, and no icon file or licence note was added. The missing icons seen in the snap therefore have another cause, which this check cannot show: for instance a different `gnome-core26` revision or channel from the one inspected, or the icon theme not being found at run time (`icon-themes` plug, `XDG_DATA_DIRS`). It has to be checked in an installed snap.

## Decision

- `crates/app/src/icon_names.rs` (a test) lists every `*-symbolic` name in `crates/app/data/*.blp` and `crates/app/src/**/*.rs` and fails unless each is bundled (`icons/scalable/actions/<name>.svg` in `resources.gresource.xml`, and the file exists in `crates/app/data/icons/scalable/actions/`) or is on `crates/app/data/gnome-core26-icons.txt`, the `*-symbolic` names under `Adwaita/symbolic/` in that snap.
- To bundle an icon later: add the SVG there and the line to the GResource; take it from adwaita-icon-theme (LGPL-3.0-or-later or CC-BY-SA-3.0, per file) with the licence noted in the file and here, or draw it; use only `fill` colours GTK recolours (no hard-coded colour).
- The list is regenerated by the command in its header when the base changes.

## Consequences

A name the snap's Adwaita lacks can no longer be added unnoticed. The icon problem seen in the snap is not fixed by this change.
