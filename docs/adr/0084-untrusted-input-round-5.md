# 84. Untrusted input, round 5: the paths of phase 3b; clean-up #5

- Status: Accepted
- Date: 2026-11-10
- Amends: ADR 0063 (rows 89 on of the untrusted-input table, after ADR 0073's rows 74 to 88), ADR 0080 (the backup removes its own leftover partial files after a day, and refuses a folder inside the data directory itself), ADR 0079 (the first header after a bulk action), ADR 0081 (the release controller's `key-pressed` handler), ADR 0076 (how often an audio control repaints its side)
- Refers to: `docs/briefs/phase-3b.md` (slice 9); ADR 0049 (time bounds), ADR 0075 to 0083

## Context

Phase 3b added new paths since 0.4.0-beta.1: the ink margin of card sides (ADR 0076), the app id rename (ADR 0075), card lists with drawn formulas and shared tags (ADR 0077) grouped by tag on the deck page (ADR 0079), the statistics a month at a time (ADR 0078), the automatic backup to a folder the user chooses (ADR 0080) and the study keys (ADR 0081). Rounds 1 to 4 (ADR 0025, 0050, 0063, 0073) kept one table per round; this is round 5, with rows 89 on. The reviews of slices 1 to 8 also left follow-ups for this slice (A to L below).

## Decision

### Method

As in rounds 2 to 4: each attack is a test; one that passes at once means the defence already held, and says so. Every fix was checked against the code without it (the test fails there). Time bounds are CPU time at the reference machine's speed (ADR 0049), about ten times the measured value, in a debug build; "release" figures were measured once with `cargo test --release` for comparison.

### What the attacks found

- **A full disk during a backup read as "something unexpected"** (row 92). The archive writer's error was wrapped as "cannot write the export", and a failed write while a media file was being copied named that media file: the automatic backup's toast blamed nothing (or the media) instead of saying the disk was full, and Export… named the wrong file. Now an IO error writing the export is an `Error::Io` on the export's own file (`write_export`, `copy_media`), so the backup says "the disk is full" and Export… names its file.
- **Leftover partial files could fill the backup folder** (row 90). A backup killed by a shutdown or a crash leaves its hidden `.Rappel backup …partial` file, as large as a backup, and ADR 0080's deletion rule never removed one. A computer often shut down while a backup runs would gather one a day without bound. See the decision below.
- **A folder inside the data directory was refused only when chosen** (row 91). A setting saved before that check existed, a data directory moved since, or a path that names the data directory another way was backed up into the data directory itself. `auto_backup::run` now refuses it too.
- **A clock at the ends of `i64`** (row 95) overflowed in `clock::local_day_start_ms`'s fallback (a debug build panicked, a release build would wrap). Only a clock no computer shows reaches it; the arithmetic now saturates.
- **The first group header after a bulk action** (carry-over B) was scrolled out by its own height; fixed below.

### The leftover partial files (decision)

The job may now delete, besides old backups, its **own** partial files: names of the exact pattern it writes (`.Rappel backup YYYY-MM-DD.rappel.<16 lowercase hex digits>.partial`, with a date that exists: `is_partial_name`), regular files only (checked without following links, and checked again just before `unlinkat`, as for backups), whose modification time is at least a day (`STALE_PARTIAL_SECONDS`, 24 hours) before the clock. A running backup is cut off after minutes (the app's five-minute cap and 30-second grace, ADR 0080), so a day-old partial file is never one being written. A time ahead of the clock is never stale. This is done at the start of every backup that opens the folder (before writing, so a computer that kills every backup still clears them; also when today's backup is already there), not only after a successful one. It extends ADR 0080's pre-approved deletion rule only to files the job wrote itself, as the brief allows; links, folders, a user's own `.partial` files and look-alike names stay (tested with each, row 90). One edge remains: a file system that reports a fixed or zero modification time (some FUSE or MTP mounts), or a clock jump of more than a day, together with two Rappel processes (a debug and a release build) backing up to one folder at the same moment, could let one remove the other's partial file; nothing is lost (the other's rename then fails, reported as "not found").

### Follow-ups from the reviews of slices 1 to 8

- **A. Two flaky export-size tests.** `the_export_and_the_import_agree_at_the_exact_size_limit` and `an_export_larger_than_an_import_reads_is_not_kept` exported twice at the clock's time, which `cards.json` holds (`exported_at`), so the compressed size differed by a few bytes between the two exports, more than the tests' slack. Root cause confirmed: nothing else in an export varies. The export inside tests now takes the time (`export_to_limited(…, now)`, and `export_into` takes it from the caller), so both tests are exact to the byte: kept at its size, refused one byte under it, and the file equals `export_bytes_at` at the same time.
- **B. The first group header after a bulk action.** `ui::selection` reads the cards again and focuses the first row at once; the new rows have no place yet, so `scroll_to` anchors the first row at the top (`gtk_list_view_get_allocation` places a row not laid out at 0) and the next layout leaves the view at the header's height (40 px under Xvfb), against ADR 0079. `ui::focus::focus_row` now also checks once at the end of the window's next layout: a handler on the surface's `layout` signal, which runs after `GtkNative`'s own allocation (connected when the window was realized, gtk/gtknative.c), sets the view back to its top if the same row still has the focus. The frame clock runs the allocation that queues before it paints (`gdk_frame_clock_run_layout` loops, gdk/gdkframeclock.c), so no frame shows the header scrolled out. It is keyed to a layout, never to frames or scrolls (the three timing-based versions failed in CI). The test reads the cards again and focuses the first row, from the top and from far down; it failed at 40 px before the fix and passed 18 runs plainly and 8 pinned to one CPU with the cairo renderer. The slice's review found the usual path still wrong: after a press on the action bar, leaving selection mode hands the focus to Select, and `scroll_to` only moves a list's focus item while the focus is outside it, so the first row never got the focus (focus on Select, header scrolled out); `focus_row` now also grabs the list's focus when it is outside the list and the list is on screen (`gtk_list_base_grab_focus` focuses that item's row). `after_a_bulk_action_the_first_groups_header_stays_in_sight` covers both the row and a bar button having the keyboard; it failed on both before. The doc comments of `focus_row` and `index_after_removal` were swapped back, and `first_card_focused` compares the window's focus with the row only.
- **C. The ink margin.** `INK_MARGIN`'s comment now says what was measured (one device pixel past the bounds, never two; two logical pixels leave the same again). The whole side repaints whenever anything in it redraws; for the audio control that is once a second while it plays: GTK's media file notifies its timestamp every 100 ms, but `gtk_label_set_label` does nothing for the text a label already has and the note shows whole seconds. ADR 0076 said "a playing sound's progress bar": there is none; corrected.
- **D. The developer in the metainfo** is now checked against About's `DEVELOPER` (now `pub(crate)`), and its id against the app id's reverse domain; the comment on the accepted AppStream remark cites ADR 0075.
- **E. The chart's height on a font size set by CSS.** gtk4-rs 0.11 has no `css_changed` to override, and the chart stored its height (`set_content_height`) from the font it was made with. It now works its height out in `measure`, from its Pango context at that moment; GTK queues a resize when the CSS font changes (`gtk_widget_real_css_changed`, `GTK_CSS_AFFECTS_TEXT_SIZE`), so the height follows (`the_height_follows_a_font_size_set_by_css`).
- **F. The automatic backup's loose ends.** The toast for a folder inside the data directory was 44 characters with no clause to cut, so it showed "Something went wrong"; it is now "Folder not allowed: a backup inside Rappel’s data folder would be lost with it. Choose a folder outside it." (French "Dossier refusé : …"), title tested in both. The check itself moved to core (`auto_backup::inside_data_dir`, by path with links resolved and by identity, see row 91) and `run` refuses such a folder (`FailureKind::InsideDataDir`, "the backup folder is inside Rappel’s data folder, …; choose another one in Preferences"). `rename_no_replace` names the three errors it falls back on; `run` says the caller passes the folder as stored, links resolved; `unreadable_text` has its translators' comment; a leap-day test covers `due` and the file name.
- **G. Study keys.** ADR 0081 said the release controller had no `key-pressed` handler; it has one that records the keycode and returns Proceed (corrected there). A comment over 100 columns in `ui/keys.rs` is wrapped. A widget test checks that the keycode recorder is a capture-phase controller and the shortcuts are bubble-phase (so the recorder sees a press first, `gtk_propagate_event_internal`, gtk/gtkmain.c), and that recording lets the press go on. GTK 4 has no public way to inject a key event, so the recorder's `key-pressed` is emitted directly.
- **H. Store listing.** README now lists `fill_scratch_db`'s `--groups` and `--history` and the automatic backup under "Recovering your data"; ARCHITECTURE.md was checked line by line against the tree (below).
- **L. `a_side_marks_its_whole_ink_at_every_snapshot` failed in a desktop session.** It snapshot the side after one turn of the main loop. Under Xvfb, with no window manager, the window is mapped and allocated in that turn; on Xwayland the compositor answers later, so the labels had no size yet ("Trying to snapshot GtkLabel … without a current allocation") and drew nothing. The test now waits until every child of the side has a size (10 s at most). It passes in the Wayland session and under Xvfb; nothing is skipped.

### Clean-up #5

- **Shared:** one `ui::text::card_count` ("1,234 cards", "No cards") replaces All Cards' `count_text`, the archived decks' `card_count` and the group headers' use of All Cards' text (a widget reached into a page for it); `render::layout_key` holds the layout key, cache size and placeholder length that `MathParagraph` and `MathLine` each had a copy of (the line's placeholder length was unchecked); `ui::keys::install_start_key` and the trait `StartKeyPage` wire S to the deck list and a deck's page, which had the same two controllers and `when_left` line for line; tests share `testing::strings` (six copies), `testing::card_rows` and, for scale tests, `testing::state_with_cards` and `math_side`.
- **Kept test-only:** `Store::first_activity_at` is `#[cfg(test)]`: the stats tests check the first activity alone against their oracle, which is clearer than through `stats_and_first_activity`.
- **Narrowed:** in core's `auto_backup`, everything the app does not use is `pub(crate)` (`KEEP`, `MAX_ZONE_SPREAD_DAYS`, `file_name`, `parse_file_name`, `to_delete`, `changed`, `kind_of`, and the new `is_partial_name`, `stale_partials`, `STALE_PARTIAL_SECONDS`); `LocalDate::from_utc_ms` and `Store::first_activity_at` are test-only (the app reads `stats_and_first_activity`); `MAX_SUMMARY_FORMULA_BYTES` is `pub(crate)`.
- **Renamed:** the deck page's tests and timings that still said "new flags" say "standings" (`refresh_standings`, ADR 0079).
- **Left, and why:** `Store::stats` stays public (a documented reading of the statistics, used by core's own tests and the archive tests). The study-days arithmetic shared by the card rows' and the deck rows' due words is one line each with different wording around it. `window_state` and `auto_backup` already share `key_file`; the remaining three-line match on its result stays in each. Making `ui::keys::starts_studying` and `card_row::update_shared_tags` private gains nothing in a binary crate. Files over 800 lines stay, as ADR 0063 said.
- **ARCHITECTURE.md** was checked line by line against the tree: every path exists; it now names the omitted `fill_scratch_db` options, `EXPORT_WITHOUT_MEDIA`, `decks.statistics`, `deck.practice`, `deck.select-card`, 3 and 4 on the review page, `used_tags_listed`, `stats_and_first_activity`, the CSS rules of the card lists, the grouping rule as the code has it (at most half of the groups holding one card), `deck_row.blp` and `card_row.blp`, and this round's additions.

## Consequences

- Seen by the user: a full disk during an automatic backup is said as such; a backup folder inside the data directory is refused at the backup too; leftover partial backups from killed backups disappear a day later; the toast for a folder inside the data directory has a real title; after a bulk action on a grouped deck page the first group's header stays in view; the statistics chart grows with a larger text set by a theme.
- The automatic backup's record can hold a new reason, `inside-data-dir`; an older Rappel reads it as "other", as it reads any unknown reason. No migration, no format change.
- The gate grows by the new scale tests (about 10 s together in a debug build).
